# Registration specs

Design: [registration-design.md](registration-design.md). Prefix `REG`.

## Entry point and `register()`

- [x] **REG-001**: The distribution `vllm-nemotron-asr-streaming` shall expose exactly one `vllm.general_plugins` entry point, named `nemotron_asr_streaming`, whose target is the plugin's `register` function.
- [ ] **REG-002**: If the installed vLLM's `ModelState` does not define each of `prepare_execution_memory`, `needs_cudagraph_capture`, `capture_cudagraphs`, `clear_cudagraphs`, `post_warmup`, `shutdown` and `take_failed_requests`, `MambaManager.layer_config` has no `recomputable` parameter, `MambaAttentionBackendEnum` has no member `PERSISTENT_STATE`, or `vllm.model_executor.models.interfaces` does not define `SupportsPersistentState`, then `register()` shall raise, without importing either model class module, an error that names each missing item and states that the plugin requires a vLLM build with RFC 1's state layer and vllm#67583's model-state hooks, and shall leave `ModelRegistry`, `MODELS_CONFIG_MAP`, the config parsers and the tokenizer modes unchanged; `register()` shall check no `AsyncLLM` call.
- [x] **REG-003**: When `register()` runs, it shall register the architecture `Nemotron3_5AsrStreamingForRNNT` with `ModelRegistry` as the lazy reference `vllm_nemotron_asr_streaming.model:Nemotron3_5AsrStreamingForRNNT`, without importing the model module.
- [x] **REG-004**: When `register()` runs, it shall set `MODELS_CONFIG_MAP["Nemotron3_5AsrStreamingForRNNT"]` to the plugin's verify-and-update class.
- [x] **REG-005**: When `register()` runs, it shall register the card parser under the config format name `nemotron_asr_streaming`.
- [x] **REG-006**: When `register()` runs, it shall register the tokenizer mode `nemotron_asr_streaming`.
- [x] **REG-007**: If the `ModelRegistry` entry or the `MODELS_CONFIG_MAP` entry for the offline architecture `Nemotron3_5AsrForRNNT` differs after `register()` from its state before `register()`, then `register()` shall raise.
- [x] **REG-008**: When `register()` is called more than once in one process, every call after the first shall leave the registrations of REG-003 to REG-006 unchanged and shall not raise.
- [x] **REG-009**: `register()` shall initialize no device and load no model weights.
- [ ] **REG-010**: If any unconditional adapter dependency listed in the registration design (module and name, including the six `ModelState` hooks `prepare_execution_memory`, `needs_cudagraph_capture`, `capture_cudagraphs`, `clear_cudagraphs`, `post_warmup` and `shutdown`, `ModelState.take_failed_requests`, the `recomputable` parameter of `MambaManager.layer_config`, the member `PERSISTENT_STATE` of `MambaAttentionBackendEnum` and `SupportsPersistentState`; every row except the conditional rows of REG-014 and REG-015) cannot be imported or is not defined when the model class module is imported, then the import shall raise an error naming every missing module and name, before any weights load.
- [ ] **REG-014**: The conditional graph-runtime dependencies shall be `vllm.distributed.parallel_state.graph_capture`, `vllm.forward_context.BatchDescriptor` and `set_forward_context`, `vllm.platforms.current_platform`, `vllm.utils.import_utils.resolve_obj_by_qualname`, `vllm.compilation.cudagraph_pool.capture_pool` and `vllm.envs.VLLM_MEMORY_PROFILER_ESTIMATE_CUDAGRAPHS`. When graphed execution is not configured (the registration design, Segment arms), their absence shall not prevent model import or construction; if any is missing when graphed execution is configured, then model construction shall raise an error naming it.
- [ ] **REG-015**: The conditional batch-invariant dependency shall be `vllm.model_executor.determinism.batch_invariant`. When vLLM's batch-invariant mode is not enabled (`VLLM_BATCH_INVARIANT` unset or false), its absence shall not prevent model import or construction; if it is missing when that mode is configured, then model construction shall raise an error naming it.
- [ ] **REG-018**: Model import and model construction shall check no transaction-graph dependency; while transaction graphs are on (TXG-CFG-001), model construction shall raise the refusal of TXG-CFG-016 (REG-ENG-006) and no dependency error for transaction graphs.
- [ ] **REG-016**: The model adapter shall use no vLLM internal dependency outside the registration design's dependency table, except the interfaces that the design explicitly excludes from that table.
- [x] **REG-012**: After importing `vllm_nemotron_asr_streaming`, running `register()` and importing `vllm_nemotron_asr_streaming.session`, neither model class module (`vllm_nemotron_asr_streaming.model`, `vllm_nemotron_asr_streaming.nemotron_asr.nemotron_asr`) shall be in `sys.modules`; the card parser's configuration module and engine modules imported by the public client and configuration APIs are allowed.
- [x] **REG-013**: Importing the model class module shall initialize no device and load no weights.

## Card parser

- [x] **REG-CARD-001**: When the card parser runs, it shall load `config.json` and `processor_config.json` from the local path given, or from the Hub repository at the requested `revision`.
- [x] **REG-CARD-002**: When the card parser receives a `config.json` that has `encoder_config`, it shall translate it as a Hub card (REG-CARD-005 to REG-CARD-010).
- [x] **REG-CARD-003**: When the card parser receives a `config.json` whose `architectures` is `["Nemotron3_5AsrStreamingForRNNT"]` and that has no `encoder_config`, it shall use it unchanged as an already-translated configuration.
- [x] **REG-CARD-004**: If the card parser receives a `config.json` that is neither a Hub card nor an already-translated configuration, then it shall raise an error naming both accepted inputs.
- [ ] **REG-CARD-005**: If a Hub card's `vocab_size` is not `blank_token_id + 1`, or its `encoder_config` has no `supported_num_lookahead_tokens` or no `default_num_lookahead_tokens`, then the card parser shall raise an error naming the field.
- [x] **REG-CARD-006**: When translating a Hub card, the card parser shall set `eos_token_id` (park), `audio_chunk_token_id` (stream chunk carrier), `eou_token_id`, `file_carrier_token_id` and `continuation_token_id` to `blank + 1` through `blank + 5` in that order, and `vocab_size` to `blank + 6`, which is also the model's logit width (the model has no separate logit-width field).
- [x] **REG-CARD-007**: When translating a Hub card, the card parser shall map the encoder fields `hidden_size`, `num_hidden_layers`, `conv_kernel_size`, `sliding_window` and `num_mel_bins` to `d_model`, `n_layers`, `conv_kernel`, `att_context_left = sliding_window − 1` and `n_mels`, raising if any is missing or not an integer; map `decoder_hidden_size` and `num_decoder_layers`, when present, to `pred_hidden` and `pred_rnn_layers`; raise if `prompt_intermediate_size` is present and not `2 × hidden_size`; and carry no other `encoder_config` field.
- [ ] **REG-CARD-008**: When translating a Hub card, the card parser shall set `architectures` to `["Nemotron3_5AsrStreamingForRNNT"]`, record `encoder_config.supported_num_lookahead_tokens` as `card_num_lookahead_tokens` and `encoder_config.default_num_lookahead_tokens` as `card_default_num_lookahead_tokens`, set `max_position_embeddings` to 2^24, set `encoder_execution_arm` to `"eager-graphed"` and `decode_dispatch_arm` to `"dense-graphed"`, and remove `model_type`, `is_encoder_decoder`, `default_prompt_id`, any top-level `sliding_window`, and any top-level `supported_num_lookahead_tokens`, `default_num_lookahead_tokens` and `num_lookahead_tokens` the card carries.
- [x] **REG-CARD-009**: For either accepted input, the card parser shall store the locale table `prompt_dictionary` from `processor_config.json` in the configuration and keep the card's `num_prompts`; if an already-translated configuration stores a table that differs from the file's, then it shall raise.
- [x] **REG-CARD-010**: When translating a Hub card that has a key with the same name as a value the translation computes (control-token IDs, `eos_token_id`, `vocab_size`, logit width, `architectures`), the card parser shall keep the computed value.
- [ ] **REG-CARD-011**: If, for either accepted input, the control-token IDs, `eos_token_id` or `vocab_size` differ from REG-CARD-006; `num_prompts` is not a positive integer or differs from `processor_config.json`'s; the locale table is missing or empty, or any of its values is not an integer row in `0 … num_prompts − 1` (several locales may share a row); `card_num_lookahead_tokens` is empty or contains a value other than 0, 1, 3, 6 and 13; or `card_default_num_lookahead_tokens` is present and is not a member of `card_num_lookahead_tokens`, then the card parser shall raise an error naming the field.
- [x] **REG-CARD-012**: The card parser's result shall depend only on the checkpoint files: it shall not read the `hf_overrides` keyword argument, except that if that argument is callable, then it shall raise an error stating that only the dictionary form of `--hf-overrides` is supported.
- [x] **REG-CARD-013**: When the card parser is called with no `hf_overrides` (as core does when deriving a generation configuration for a checkpoint without `generation_config.json`), it shall succeed, and the configuration it returns shall yield a generation configuration whose only EOS is `blank + 1` and that sets no token limit.
- [x] **REG-CARD-014**: The card parser shall return the configuration dictionary and an instance of the model's configuration class `NemotronASRConfig` built from it, whose `hidden_size` is the stream carrier row width 17,927 and whose `num_asr_labels` is `blank`.
- [x] **REG-CARD-015**: The session, the packer, the file prompt and the model shall take every control-token ID from the served configuration, never from a constant.
- [x] **REG-CARD-016**: The model class attribute `realtime_max_tokens`, the session's `max_tokens` (SESS-ENG-001) and the threshold of REG-VAL-001 shall all take their value from one definition in the geometry manifest module.

## Tokenizer mode

- [x] **REG-TOK-001**: When the tokenizer mode `nemotron_asr_streaming` loads a tokenizer, it shall load the card's tokenizer, keep any special tokens the card already has at IDs `blank` to `blank + 5` (the published card has `<pad>` at `blank` and `<blank>` at `blank + 1`), and append tokens for the remaining IDs up to `blank + 5`, so that every ID from `blank` to `blank + 5` is special in both senses core's detokenizers use: flagged special in the tokenizer backend, and listed in the tokenizer's `all_special_ids`.
- [x] **REG-TOK-002**: The tokenizer loaded by the tokenizer mode `nemotron_asr_streaming` shall set its EOS to the token at `blank + 1` (`eos_token_id == blank + 1`), replacing any EOS the card tokenizer declares, and shall report no other EOS token.
- [x] **REG-TOK-003**: If any token appended by the tokenizer mode `nemotron_asr_streaming` is assigned an ID other than its expected ID, then loading the tokenizer shall raise.
- [x] **REG-TOK-004**: The tokenizer mode `nemotron_asr_streaming` shall take `blank` from `blank_token_id` in the `config.json` beside the tokenizer; if that file has none, the card tokenizer's base vocabulary size differs from it, or the card tokenizer has a token at an ID of `blank` or more that is not special or is above `blank + 5`, then loading the tokenizer shall raise.

## Server geometry and post-override validation

These checks run in `verify_and_update_model_config`, after core has applied every
`--hf-overrides` key, and apply to both accepted inputs, except where a spec names
`verify_and_update_config`. The server's lookahead is the value REG-LA-001 defines.

- [ ] **REG-LA-001**: The function `served_lookahead(hf_config)` in `vllm_nemotron_asr_streaming.lookahead` shall return the server's lookahead: `num_lookahead_tokens` when the configuration has it (from `--hf-overrides`, or stored by an already-translated configuration), and `card_default_num_lookahead_tokens` otherwise; if neither is present, or the value is a `bool`, is not an integer, or is not one of the implemented right contexts 0, 1, 3, 6 and 13, then it shall raise `ValueError` naming the field.
- [ ] **REG-LA-002**: If the server's lookahead is a `bool`, is not an integer, or is not one of the implemented right contexts 0, 1, 3, 6 and 13, then startup shall fail with an error naming the field it came from, the value and the implemented right contexts.
- [ ] **REG-LA-003**: When the server's lookahead is valid and `card_num_lookahead_tokens` does not contain it, startup shall log a warning naming it as a geometry the checkpoint does not declare, and shall not fail for that reason.
- [ ] **REG-LA-004**: If the final configuration has neither `num_lookahead_tokens` nor `card_default_num_lookahead_tokens`, then startup shall fail with an error stating that the server's lookahead must be set with `--hf-overrides '{"num_lookahead_tokens": <N>}'` and naming the implemented right contexts.
- [ ] **REG-LA-006**: When the server's lookahead is valid, `verify_and_update_model_config` shall set the served configuration's `att_context_right` to it.
- [ ] **REG-LA-007**: Where native burst is supported on the running core (no state-layer core; REG-ENG-019), if `experimental_native_burst` is true and the server's lookahead is not 1, then startup shall fail with an error naming both values.
- [ ] **REG-LA-008**: If the final configuration has `supported_num_lookahead_tokens` (from `--hf-overrides` or stored by an already-translated configuration), then startup shall fail with an error stating that a server serves one geometry, selected with `num_lookahead_tokens`, and that `supported_num_lookahead_tokens` must be removed.
- [ ] **REG-LA-009**: Every component that reads the server's lookahead, including the model's warmed and captured geometry, its per-row geometry check, the session factory, `buffer_realtime_audio`, `get_generation_prompt`, the processor's header check (FILE-PROMPT-006) and native burst's configuration check, shall obtain it only by calling `served_lookahead` (REG-LA-001) on the served configuration.
- [x] **REG-VAL-001**: If, in the final configuration, the control-token IDs, `eos_token_id` or `vocab_size` differ from REG-CARD-006, any schema condition of REG-CARD-011 fails, or `max_model_len` is less than `1 + realtime_max_tokens` (143 for the implemented geometries), then startup shall fail with an error naming each.
- [x] **REG-VAL-002**: If `language_locales` is given and any entry's value is not a key of the locale table, or its key is not that locale's language (the lowercase letters before the first `-` or uppercase letter, when there are two or three of them; `auto` has none), then startup shall fail with an error naming the entry.
- [ ] **REG-VAL-003**: If any check of REG-LA-002, REG-LA-004, REG-LA-007, REG-LA-008, REG-VAL-001, REG-VAL-002, REG-VAL-005, REG-VAL-006, REG-VAL-008, REG-ENG-002 to REG-ENG-005, REG-ENG-009, REG-ENG-019 or REG-ENG-030 fails, then the configuration hook running it (`verify_and_update_model_config` or `verify_and_update_config`), or the model construction or model-state construction of REG-ENG-006, shall raise one `ValueError` that lists every failed check of that hook, not only the first. For a setting that core's persistent-state check refuses before the configuration hook runs (Engine settings, below), this holds for `verify_and_update_config` called directly; a configuration that core builds fails first with core's message, which names one setting.
- [x] **REG-VAL-004**: When `verify_and_update_model_config` runs, it shall log each language that FILE-LANG-002 cannot map (its locales use several distinct rows, no locale is named for the language itself, and `language_locales` has no entry for it).
- [x] **REG-VAL-005**: If `model_config.try_get_generation_config()` has an `eos_token_id` other than `blank + 1` alone, then startup shall fail with an error naming `--generation-config <dir>` with a generation configuration that has no other EOS.
- [x] **REG-VAL-006**: If `model_config.get_diff_sampling_param()` contains `max_tokens`, then startup shall fail with an error naming `--generation-config vllm` and the removal of any token-limit `--override-generation-config`.
- [ ] **REG-VAL-007**: Post-override validation shall not change `encoder_execution_arm` or `decode_dispatch_arm`; when `--hf-overrides` sets either, the served configuration shall carry the override's value.
- [ ] **REG-VAL-008**: When `verify_and_update_config` runs, it shall evaluate the transaction-graph configuration checks (`transaction_graph_config_errors`, owned by the `transaction-graph` design's Configuration checks) on the engine configuration, after `verify_and_update_model_config` resolved the server's geometry, and shall include every condition they return, among them the refusal of native burst while transaction graphs are on (TXG-CFG-001).

## Engine settings

Core's persistent-state check runs while core builds the engine configuration, before the
configuration hook, and raises `ValueError` naming the first setting it refuses: prefix caching, a
KV or EC connector, speculative decoding, a pipeline, data or tensor parallel size above 1, and,
for a model that declines synthetic warmup, fault tolerance and elastic expert parallelism (the
registration design, Engine settings, Core's checks first). For those settings REG-ENG-002 to
REG-ENG-004 describe `verify_and_update_config` called directly; a configuration that core builds
fails with core's message.

- [ ] **REG-ENG-001**: `verify_and_update_config`, model construction and the model state's construction shall not refuse a configuration on account of its `async_scheduling` value (`True`, `False` or unset), except a configuration that REG-ENG-030 refuses.
- [x] **REG-ENG-002**: If `enable_prefix_caching` is `True` in the configuration, then `verify_and_update_config` shall refuse the configuration.
- [ ] **REG-ENG-003**: If speculative decoding, KV transfer, dual-batch overlap, sleep mode, the cumem allocator, hierarchical sparse attention, fault tolerance (`parallel_config.enable_fault_tolerance`) or elastic expert parallelism (`parallel_config.enable_elastic_ep`) is enabled, then `verify_and_update_config` shall refuse the configuration, naming each enabled setting.
- [ ] **REG-ENG-008**: Where native burst is supported on the running core (no state-layer core; REG-ENG-019), the native-burst configuration check shall count a parallel setting that the running build does not define as 1, and an undefined expert-parallel setting as off.
- [x] **REG-ENG-004**: If any of the tensor, pipeline, data, decode-context or prefill-context parallel sizes that the running vLLM build defines is other than 1, then `verify_and_update_config` shall refuse the configuration; a parallel setting the build does not define shall count as 1.
- [ ] **REG-ENG-005**: If `enforce_eager` is not set and any condition of REG-ENG-021 to REG-ENG-025 (the hook configuration) is unmet, then `verify_and_update_config` shall refuse the configuration, naming each unmet condition with the remedy its spec gives; every remedy that names `--enforce-eager` shall also name removing `transaction_graph_populations` while transaction graphs are on.
- [ ] **REG-ENG-006**: When the model is constructed, and when the model state is constructed, each shall re-check REG-ENG-002 to REG-ENG-005, REG-ENG-009, REG-ENG-019 and REG-VAL-008 against the final engine configuration, refusing an unset `cudagraph_mode` or compilation mode and reading breakable graphs from the resolved `compilation_config.use_breakable_cudagraph`, and shall raise as in REG-VAL-003 if any fails.
- [ ] **REG-ENG-011**: While `enforce_eager` is not set and breakable graphs (REG-ENG-022) are off, `verify_and_update_config`, model construction and the model state's construction shall not refuse a configuration on account of a `cudagraph_mode` of NONE, PIECEWISE, FULL_DECODE_ONLY or FULL_AND_PIECEWISE combined with a compilation mode of NONE, `DYNAMO_TRACE_ONCE` or `VLLM_COMPILE`, and `verify_and_update_config` shall not refuse one on account of an unset `cudagraph_mode` or compilation mode, or of a requested `STOCK_TORCH_COMPILE` while `TORCH_COMPILE_DISABLE=1` is set, except a configuration that REG-ENG-030 refuses.
- [ ] **REG-ENG-026**: While `enforce_eager` is not set and breakable graphs (REG-ENG-022) are on, `verify_and_update_config` shall not refuse a configuration on account of a `cudagraph_mode` of NONE, FULL_DECODE_ONLY or FULL_AND_PIECEWISE, or an unset one, with any requested compilation mode, and model construction and the model state's construction shall not refuse one on account of a `cudagraph_mode` of NONE, FULL_DECODE_ONLY or FULL_AND_PIECEWISE with compilation mode NONE, except a configuration that REG-ENG-030 refuses.
- [ ] **REG-ENG-021**: The hook configuration's graph-mode condition shall be that `cudagraph_mode` is not FULL; its remedy shall be `-cc.cudagraph_mode none` or leaving the option unset.
- [ ] **REG-ENG-022**: The hook configuration's breakable-piecewise condition shall be that `cudagraph_mode` is not PIECEWISE while breakable graphs are on, where breakable graphs are on, in `verify_and_update_config`, when `VLLM_USE_BREAKABLE_CUDAGRAPH` is set to `1` and, at model and model-state construction, when `compilation_config.use_breakable_cudagraph` is true; its remedy shall be `VLLM_USE_BREAKABLE_CUDAGRAPH=0` or `-cc.cudagraph_mode none`.
- [ ] **REG-ENG-023**: The hook configuration's compilation-mode condition shall be that the compilation mode is not `STOCK_TORCH_COMPILE`, except that `verify_and_update_config` shall treat a requested `STOCK_TORCH_COMPILE` as met while breakable graphs are on or `TORCH_COMPILE_DISABLE=1` is set (core then sets the mode to NONE); its remedy shall be `-cc.mode none` or leaving the option unset.
- [ ] **REG-ENG-024**: The hook configuration's platform condition shall be a CUDA platform; its remedy shall be `--enforce-eager`.
- [ ] **REG-ENG-025**: The hook configuration's graph-selection condition shall be that at least one hook-captured graph is selected, namely `encoder_execution_arm` `eager-graphed`, `decode_dispatch_arm` `dense-graphed` or transaction graphs on (TXG-CFG-001) (remedy: select `encoder_execution_arm` `eager-graphed` or `decode_dispatch_arm` `dense-graphed`, or `--enforce-eager`), and that `encoder_execution_arm` is not `dense-graphed` and `chunk_bucket_graph_populations` is empty (remedy `--enforce-eager`).
- [ ] **REG-ENG-027**: `verify_and_update_config`, model construction and the model state's construction shall evaluate REG-ENG-021 to REG-ENG-025 through one function of `engine_flags`.
- [ ] **REG-ENG-016**: The model state's `get_additional_cg_support()` shall return `AttentionCGSupport.NEVER` with a backend name that names the plugin's model state.
- [ ] **REG-ENG-012**: When core's mode resolution (`CompilationConfig.resolve_cudagraph_mode_and_sizes`) runs on a configuration that the model state's construction accepts under REG-ENG-011 or REG-ENG-026, as core's configuration build leaves it on a CUDA platform (breakable graphs, `TORCH_COMPILE_DISABLE`, each optimization level's defaults for an unset mode, and the piecewise normalization applied), with the support of REG-ENG-016 and `piecewise_capture_available` equal to the resolved breakable setting (the model class has no compiled submodule), it shall yield `cudagraph_mode` NONE; and the model's set of segment-graph entry keys (encoder CHUNK counts, decoder tiers) under that configuration shall equal its set under `-cc.cudagraph_mode none -cc.mode none` for the same served configuration.
- [ ] **REG-ENG-017**: If the resolved `cudagraph_mode` is not NONE when core calls the model state's `initialize_kv_cache`, then the model state shall raise before any graph is captured, naming the resolved mode and stating that the model captures its own graphs and supports no runner graph.
- [ ] **REG-ENG-029**: If core calls the model state's `prepare_dummy_inputs`, or its `prepare_attn` for a capture or with `cudagraph_mode` FULL, then the model state shall raise, stating that the model captures its own graphs and supports no runner graph.
- [ ] **REG-ENG-018**: While `enforce_eager` is not set, when core first calls the model state's `initialize_kv_cache` in a process, the model state shall log once that core's runner captures no graph over the model's forward and that the model captures its own graphs through the capture hook, naming the `cudagraph_mode` and compilation mode its construction saw and the resolved `cudagraph_mode`.
- [ ] **REG-ENG-019**: If `experimental_native_burst` is true, then `verify_and_update_config`, model construction and the model state's construction shall refuse the configuration, stating that native burst is not supported on the state layer and naming its removal as the remedy.
- [ ] **REG-ENG-020**: When a step runs device work that reads a request's staged inputs or state, the model shall record that step's commit event after the last such read, and the model state's `postprocess_state` for that step shall wait for that event before it reads the step's commit status and before it returns.
- [ ] **REG-ENG-028**: While `enforce_eager` is not set on CUDA, under `-cc.cudagraph_mode none -cc.mode none` and under a serve command without runner flags, core's runner CUDA graph manager shall capture no graph, core shall compile no part of the model, and the model shall capture its graph inventory of REG-ENG-012 through `capture_cudagraphs`.
- [ ] **REG-ENG-013**: While a server runs on an A40 at any chunk size the model configuration allows (80, 160, 320, 560 and 1120 ms, one per server, fixed at startup), the realtime workload (the first 200 LibriSpeech test-clean utterances in the harness's fixed order through `/v1/realtime`, 32 concurrent sessions, paced at real time, with the same segment arms, `--max-num-seqs`, `--max-model-len`, dtype and budget setting in every server of a chunk size) shall produce, under `-cc.cudagraph_mode none -cc.mode none --no-async-scheduling` and under `--no-async-scheduling` alone, the same final transcript for every utterance as under `--enforce-eager --no-async-scheduling`.
- [ ] **REG-ENG-014**: While `--async-scheduling` is set, both alone and with `--enforce-eager`, the workload and chunk sizes of REG-ENG-013 shall produce the same final transcript for every utterance as under `--enforce-eager --no-async-scheduling`.
- [ ] **REG-ENG-015**: While `VLLM_BATCH_INVARIANT=1`, on one server per chunk size of REG-ENG-013 with `--async-scheduling`, a `--max-num-seqs` of at least 32 and no runner flag, every utterance of REG-ENG-013's workload shall have the same final transcript at 32 concurrent sessions as at 8, and each of its first 20 utterances the same final transcript at 1 concurrent session.
- [ ] **REG-ENG-031**: While `--async-scheduling` is set, the plugin's `gpu` test tier, which covers stream and whole-file aborts and steps with only finished requests, shall pass on an A40 as it does under `--no-async-scheduling`.
- [ ] **REG-ENG-032**: When the engine starts on CUDA with the extensible KV cache at its default, under `--enforce-eager` and under the hook configuration, the model state's `add_request` shall receive no request before the first client request, and startup shall complete.

## Execution memory

A dummy step is a step one of whose rows carries a request ID that the model state does not hold
(REG-STATE-011) when its `prepare_inputs` classifies the step, after deciding any pending removal:
a request it never recorded, or one it has retired. A real step is any other step. A profiling dummy step is a dummy step for which core
called no `prepare_attn` since the previous `prepare_inputs`. The segment graphs, graphed execution and the hook configuration are those of
the registration design (Segment arms, Engine settings). The profile transaction's maximum shape is
`max_num_seqs` rows at the server's geometry and each configured CHUNK-bucket graph population;
transaction graphs add no shape to it. Transaction graphs are on or off as TXG-CFG-001 defines,
decided by `transaction_graphs_on` (TXG-CFG-014).

- [ ] **REG-MEM-001**: When the model state's `prepare_inputs` runs, it shall classify the step as a real step, a dummy step or a profiling dummy step by the definitions above and record the classification, replacing any earlier record, and shall not prepare execution itself.
- [ ] **REG-MEM-002**: When the model's forward runs on the first profiling dummy step of a worker under `--enforce-eager`, it shall capture the configured segment graphs for the server's geometry, verify readiness of every configured execution entry and capture of every configured graph entry (each encoder CHUNK count and decoder tier of a graphed arm, and each configured CHUNK bucket), then, with every captured graph retained, run the profile transaction at its maximum shape, and return the dummy output core expects (a tensor shaped like the input embeddings).
- [ ] **REG-MEM-003**: When the model's forward runs on a later profiling dummy step of a worker whose preparation succeeded, including one that core runs after it has bound the state pages, it shall verify readiness as in REG-MEM-002 (under the hook configuration accepting segment graphs that the serving capture has not yet captured) and return the dummy output without capturing, re-running the profile transaction or reading any state page.
- [ ] **REG-MEM-004**: If any step of REG-MEM-002, REG-MEM-016 or REG-MEM-018 fails, then the model shall discard its partial execution state, synchronize the device, mark the worker's preparation failed and raise; any later profiling dummy step in that worker shall raise without preparing.
- [ ] **REG-MEM-005**: Preparation and warm-up (REG-MEM-002, REG-MEM-018), the profile transaction (REG-MEM-002, REG-MEM-016) and segment-graph capture (REG-MEM-002, REG-MEM-020, REG-MEM-022), in either runner configuration, shall use model-owned scratch state built from the model's state layout (`StateLayout`) and shall read neither the state layer's views nor any state page.
- [ ] **REG-MEM-006**: If a real step would use graphed execution and any expected segment-graph entry is not captured in its graph wrapper (the wrapper's entry holds no graph), then the model shall raise without capturing; the absence of a transaction-graph cell follows TXG-COV-006 and TXG-EXEC-013.
- [ ] **REG-MEM-007**: The model's graph runtime shall capture through core's graph-capture context, forward context and the platform's static graph wrapper, shall neither import nor call a capture-enabled switch, and, under the hook configuration, shall capture on the `stream` core passes to `capture_cudagraphs`, inside `capture_pool` with the `graph_pool` core passes, creating no stream and no graph pool of its own.
- [ ] **REG-MEM-009**: When the model's forward runs on a dummy step that is not a profiling dummy step, including a kernel warm-up step that core runs after it has bound the state pages, it shall return the dummy output without capturing, without running the profile transaction and without reading any state page or any request the model state recorded.
- [ ] **REG-MEM-012**: When `prepare_inputs` runs on a dummy step (profiling or not, before or after core has bound the state pages), the model state shall return a projection that reads no state page, without reading the state layer's views, any request it recorded or any input retained from an earlier step.
- [ ] **REG-MEM-010**: The dummy output of REG-MEM-002, REG-MEM-003, REG-MEM-009 and REG-MEM-016 shall have the input embeddings' token count, width, dtype and device, with every carrier-column value a valid decision ID (zero).
- [ ] **REG-MEM-013**: When core samples a dummy output, the model's sampler hooks shall read no state page.
- [ ] **REG-MEM-011**: If a real step schedules any row for model execution and preparation has not succeeded in this worker, then the model shall raise without preparing.
- [ ] **REG-MEM-014**: When a real step schedules no row for model execution (cleanup only), the model shall complete it whether or not preparation has succeeded.
- [ ] **REG-MEM-008**: The model's forward shall not run a forward-time profile of an unprepared encoder on a profiling dummy step; REG-MEM-002 and REG-MEM-016 are the only profiles the model runs.
- [ ] **REG-MEM-015**: When the model captures segment graphs (the profiling dummy step under `--enforce-eager`, or each `capture_cudagraphs` call under the hook configuration), it shall log one INFO line naming the runner configuration, the capture (profiling dummy step, profiling capture or serving capture), the encoder and decoder arms, the server's geometry, `max_num_seqs`, the graph memory the capture retained (measured by REG-MEM-027; while transaction graphs are on, the span of the call's segment-graph part only) and the capture time.
- [ ] **REG-MEM-016**: When the model's forward runs on the first profiling dummy step of a worker under the hook configuration, it shall verify readiness of every configured execution entry except the segment graphs, run the profile transaction at its maximum shape over the arms' uncaptured paths, and return the dummy output, capturing no graph.
- [ ] **REG-MEM-017**: If a segment-graph capture fails (an allocation failure or any other error, on the profiling dummy step under `--enforce-eager` or in a `capture_cudagraphs` call), or, in a `capture_cudagraphs` call whose entry checks passed, the transaction-graph part (TXG-LIFE-012) or the aggregate memory comparison (REG-MEM-022, TXG-MEM-005) fails, then, before propagating, the model shall discard every segment graph and segment-graph buffer that capture or call created and synchronize the capture stream; a failure outside the segment-graph capture shall propagate unchanged, and a segment-graph capture failure shall raise an error chained from the original that names the encoder and decoder arms, the server's geometry, `max_num_seqs`, the graph whose capture failed (encoder CHUNK count, decoder tier, or CHUNK-bucket geometry and count), the graph memory retained so far, the capture time so far, the budget setting, and the remedies: a smaller `--max-num-seqs`; or `--hf-overrides` setting `encoder_execution_arm` `eager` and `decode_dispatch_arm` `dense-eager` with `chunk_bucket_graph_populations` and `transaction_graph_populations` empty, together with `--enforce-eager`; under a fixed `--kv-cache-memory-bytes`, also a smaller value; for a serving capture under a profiled budget, also a lower `--gpu-memory-utilization`; in every case, the propagated error, its cause and context included, shall hold no reference to the tensors or graphs that capture or call created.
- [ ] **REG-MEM-018**: When core calls `prepare_execution_memory`, the model shall allocate its long-lived working memory and warm its uncaptured execution, in both runner configurations, and shall capture no graph and run no profile transaction there.
- [ ] **REG-MEM-019**: `needs_cudagraph_capture()` shall return true exactly when the platform is CUDA and the configuration selects a hook-captured graph (`encoder_execution_arm` `eager-graphed`, `decode_dispatch_arm` `dense-graphed`, or transaction graphs on, TXG-CFG-001), and shall return the same value on every call for the model state's lifetime.
- [ ] **REG-MEM-020**: When `capture_cudagraphs(profile_only=True)` runs and no entry check refuses the call (REG-MEM-024, TXG-LIFE-007), the model shall capture the segment graphs for the server's geometry into the pool and on the stream core passes before any transaction-graph cell, and, while transaction graphs are off, shall end the call by allocating the charged margin (one device buffer of the transaction-graph design's margin size, held until `clear_cudagraphs`) and recording its retained charge, both through REG-MEM-027.
- [ ] **REG-MEM-021**: When `clear_cudagraphs()` runs, the model shall release every segment graph and segment-graph buffer that the profiling capture created, and the margin it created while transaction graphs are off (TXG-LIFE-005 releases it while they are on), keeping only host-integer figures of that capture, and shall complete without error when nothing was captured.
- [ ] **REG-MEM-022**: When `capture_cudagraphs(profile_only=False)` runs and no entry check refuses the call (TXG-LIFE-007 and TXG-LIFE-008 while transaction graphs are on; REG-MEM-024; then TXG-MEM-009 while transaction graphs are on or REG-MEM-023 while they are off), the model shall rebuild the segment graphs by the procedure of REG-MEM-020, without the margin, into core's global graph pool; while transaction graphs are off and a profiling capture ran in the worker, if the serving call's retained graph memory exceeds the profiling call's (margin charge included), by the aggregate comparison of REG-MEM-027, then startup shall fail with an error naming both totals, the margin's charge, the excess and the remedies of REG-MEM-017.
- [ ] **REG-MEM-023**: When `capture_cudagraphs(profile_only=False)` runs while transaction graphs are off and no profiling capture ran in the worker, the model shall decide at the call's entry, after REG-MEM-024 and before capturing any segment graph, by the required-capture predicate of REG-MEM-027, from the worker's effective cache configuration, whether one was required; if it was required, then the call shall fail startup there with an error naming the configuration that should have run core's graph-memory estimate; if it was not required, then after the capture it shall log one WARNING that the segment graphs were not charged to the budget, with the reason and their retained graph memory.
- [ ] **REG-MEM-024**: If `capture_cudagraphs(profile_only=False)` runs after a serving capture was attempted in the worker (a serving call that passed its entry checks, REG-MEM-022), whether or not the attempt succeeded, or `capture_cudagraphs(profile_only=True)` runs after a serving capture was attempted, or either capture call runs while profiling segment graphs exist, then the model shall raise at the call's entry, after the transaction-graph entry checks (TXG-LIFE-007, TXG-LIFE-008) while transaction graphs are on, without capturing; the first error shall state that recapture over live state pages is not supported and that recovery is an engine restart, and, while transaction graphs are on, each error shall name `transaction_graph_populations`.
- [ ] **REG-MEM-025**: When `post_warmup()` runs, in either runner configuration, the model shall verify that every expected segment-graph entry holds its graph, before the transaction-graph verification, and shall raise if any does not; that check shall allocate nothing and replay no graph.
- [ ] **REG-MEM-026**: When `shutdown()` runs, the model shall release every segment graph and segment-graph buffer, and shall complete without error for a model state whose initialization did not complete or that captured nothing.
- [ ] **REG-MEM-027**: The model shall have one implementation, owned by the segment-graph part and called by the transaction-graph part for its spans (TXG-MEM-001, TXG-MEM-004, TXG-MEM-005, TXG-MEM-007), of: a span's retained graph memory, the drop in `torch.cuda.mem_get_info` free memory across it, each reading taken after synchronizing the capture stream and releasing the allocator's unused cached blocks; the charged margin's allocation and its retained charge `r`, the drop across that allocation; the required-capture predicate (the effective `kv_cache_memory_bytes` unset or 0, `VLLM_MEMORY_PROFILER_ESTIMATE_CUDAGRAPHS` not 0, and the effective extensible KV cache off); and the aggregate comparison of a serving call total against a profiling call total that includes `r`.
- [ ] **REG-MEM-028**: Where vLLM's current platform reports no static graph mode, or a segment-graph entry's device type is not the platform's device type, the model's graph runtime shall bind each segment-graph entry to a wrapper that holds a non-device graph from construction and runs the entry's runnable eagerly on every call, shall capture, pool and synchronize nothing for it, shall serve the graphed arms through that wrapper with outputs equal to the eager transition's, and shall log one INFO line naming each graphed arm it serves through that wrapper.

## Model-state interface

- [ ] **REG-MS-001**: Every `ModelState` method the model state overrides shall accept every call that the base method's signature at the target core accepts (same positional parameters, keyword-only parameters and defaults).
- [ ] **REG-MS-002**: When `dummy_inputs_embeds(num_tokens, input_ids)` is called, with `input_ids` a tensor or `None`, the model state shall return its pre-allocated embeddings buffer sliced to `num_tokens`.
- [ ] **REG-MS-003**: When the model state's `postprocess_state` runs for a real step, it shall record as failed every request of the step whose collected row status resolved to a nonzero value, every request of the step's planning-failed set (TXG-FAIL-008) and every file request that FILE-QC-012 fails, by its worker request ID, and shall raise no error on account of those rows; on a dummy step it shall record none.
- [ ] **REG-MS-004**: When core calls the model state's `take_failed_requests()`, it shall return the set of request IDs recorded by REG-MS-003 since the previous call and clear the record, or `None` when none is recorded.
- [ ] **REG-MS-005**: While the plugin's `gpu` test tier runs on the target core, a request that `take_failed_requests` returns shall end with finish reason `error` and every other request of its step shall continue; a returned ID that core's scheduler no longer holds shall end no request and raise no error.
- [ ] **REG-MS-006**: If `postprocess_state` raises, then the model state shall first drop the step's plan and shall record no failed request for that step.

## State-slot access

A request's slot is its one block in the model's state group; a state page is that block's memory.
A *file request* is a request whose scheduled token at its first `add_request` is the file carrier;
every other request is a *stream request*. The model state *holds* a request from its
`add_request` until it retires the request. A held request is *pending removal* from a
`remove_request` for it until the model state decides that removal (REG-STATE-011), and *live*
otherwise. An `add_request` *continues* a request when the request is pending removal and the call
has `num_computed_tokens` above 0 and the same slot.

- [ ] **REG-STATE-001**: The state layer shall declare a `MambaSpec` whose `shapes` and `dtypes` are the state layout's descriptors in manifest order, with `state_alignment` 1 and `block_size` equal to `max_model_len`, and shall return `MambaManager.layer_config(spec, recomputable=False)` as its KV-cache configuration; if the spec's `page_size_bytes` differs from the layout's page size, then it shall raise an error naming both sizes.
- [ ] **REG-STATE-002**: When core calls the model state's `add_request`, the model state shall take the request's slot from `block_ids[0][0]` of the delivered `NewRequestData`, and shall raise an error naming the request unless `block_ids` holds exactly one group and that group holds exactly one block; it shall give the request a new admission generation from its own counter unless the call continues the request (REG-STATE-011).
- [ ] **REG-STATE-003**: During a real step, the model shall read and write state only through the state layer's per-state views as core has bound them at that step, for the slots of the step's rows; if any row's slot is not between 1 and the bound block count minus 1, then it shall raise before it reads or writes any page.
- [ ] **REG-STATE-004**: When the model commits state for a step, it shall first check that the commit's row order and slots equal the step's row bindings; if they differ, then the model shall write no state.
- [ ] **REG-STATE-005**: The model's projection of the state layer's views into named state tensors shall take the views and the model's `StateLayout` and read nothing else.
- [ ] **REG-STATE-006**: File-row planning, initialization and commits shall follow REG-STATE-003, REG-STATE-004 and REG-STATE-010 as stream rows do.
- [ ] **REG-STATE-007**: When the model state takes a file request at its `add_request`, it shall read only the delivered `NewRequestData` and host data.
- [ ] **REG-STATE-008**: When a real step schedules a row, the model state shall take that row's scheduled token from the prompt it recorded at the request's latest `add_request`, at the row's `num_computed_tokens` (core delivers a continuing turn with a compacted prompt, one frontier token followed by the turn's input, and `num_computed_tokens` 1), and shall plan a position past that prompt as a sampled, non-CHUNK token without reading device memory; if the scheduled window crosses the end of the prompt, then it shall fail that row at planning (REG-STATE-015) and shall not raise. For a file request this classifies only the scheduled token's origin; FILE-ROW-002 determines whether the row executes as CHUNK before transaction classification.
- [ ] **REG-STATE-009**: The state layer's `MambaSpec`, and the layer's own `mamba_type`, shall have `mamba_type` `MambaAttentionBackendEnum.PERSISTENT_STATE`.
- [ ] **REG-STATE-010**: When a real step schedules a row whose `num_computed_tokens` is 0, the model shall, on the current stream and before the step's transaction reads or writes that row's page, zero every byte of the page and write each state-layout descriptor's non-zero initializer into it.
- [ ] **REG-STATE-011**: When core calls the model state's `remove_request` for a live stream request, the model state shall hold the request pending removal until its next call of `add_request`, `remove_request`, `prepare_attn` or `prepare_inputs`; if that call is an `add_request` that continues the request, then the model state shall keep the request's admission generation and replace its recorded prompt and `NewRequestData`; on any other of those calls it shall first retire the request, dropping its recorded prompt, slot and admission generation.
- [ ] **REG-STATE-016**: When core calls the model state's `remove_request` for a file request it holds, the model state shall retire the request within that call, dropping its recorded prompt, slot, admission generation, file buffer, file progress and failed-file mark, also on a step that runs no forward work, and shall hold no file request pending removal.
- [ ] **REG-STATE-012**: If core calls the model state's `add_request` for a live request, whatever the call's `num_computed_tokens`, 0 included, then the model state shall raise an error naming the request. Separately, if core calls `add_request` with `num_computed_tokens` above 0 and the call continues no request, then the model state shall raise an error naming the request.
- [ ] **REG-STATE-013**: If, when core calls the model state's `initialize_kv_cache`, the KV-cache configuration does not have exactly one group whose only layer is the state layer, or core has not bound the state layer's views, then the model state shall raise an error naming the groups it received.
- [ ] **REG-STATE-014**: If a real step schedules more than one token for a row, then the model state shall fail that row at planning (REG-STATE-015), classifying none of its tokens, and shall not raise; the step's other rows shall execute and commit.
- [ ] **REG-STATE-015**: If a real step's row has a fault that its request's own prompt or multimodal items cause, as a direct engine client can send them (among them the window of REG-STATE-008, the multi-token row of REG-STATE-014, the geometry of SESS-MODEL-001 and SESS-MODEL-002, and the file item of FILE-PROMPT-007), then the model state shall fail that row at planning through the row-failure path (TXG-COV-010, TXG-FAIL-008), so that its request alone ends with finish reason `error` through `take_failed_requests` (REG-MS-003, REG-MS-004), and shall not raise for it; for a violation of core's model-state contract (REG-STATE-002, REG-STATE-003, REG-STATE-012) it shall raise.
- [ ] **REG-STATE-017**: If a step's collected status report names a request and admission generation that the model's session registry does not hold as current (the request was retired, or retired and admitted again, after the step was planned), then `collect_commit_status` shall resolve that report's status as nonzero, so that REG-MS-003 records the request as failed, shall return no `QueueCount` for it and shall publish none of its progress.
